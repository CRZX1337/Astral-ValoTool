Lock your Valorant agent before anyone else in the lobby finishes loading.

Picking an agent in pre-game usually comes down to whose client loaded first and who moved their mouse fastest. Astral listens to Valorant's local client API instead, and hovers and locks your agent the second pre-game opens.

Features

One process, and it does the waiting for you.

It's one C# app: an embedded ASP.NET Core Web API behind a native WebView2 window. Use the dark-mode desktop UI, or skip it entirely and talk to the local REST endpoints from your own scripts.

Locks the instant pre-game opens

Detects the pre-game lobby and locks your agent through RadiantConnect. It watches your local game client for the state change rather than the screen, so there is no mouse to move and nothing to react to.

Pre-game detection Auto hover + lock Match de-duped

Per-map overrides

Sova on Ascent, Viper on Breeze, Omen on Lotus, and your main everywhere else. Astral resolves the map before it picks.

Millisecond timing

Hover, lock, and post-lock delays in milliseconds if you want the pick to look less instant. Anything from 0 to 10 000 ms.

Live state stream

Server-Sent Events on /api/state/stream, so the UI and any external client stay current without polling.

Keeps running in the tray

Closing the window sends Astral to the system tray. The lock loop keeps running — right-click the icon to stop or exit.

Real agent art

Agent portraits and role icons are fetched from valorant-api.com at runtime, so a new agent shows up without an update.

Nothing to install

The whole web frontend is embedded in the binary. One self-contained Astral.exe, and nothing gets written next to the executable.

How it works

Four steps, then you stop thinking about it.

Start Astral

Idle
  1. 1

    Launch it, whenever

    Start Astral.exe either before or during a Valorant session. It binds Kestrel to a random loopback port and opens the desktop UI.

  2. 2

    Pick your main

    Choose from the agent grid. Press / to jump straight to the search box, and add per-map overrides if you swap agents depending on the map.

  3. 3

    Hit Start Locking

    Astral watches your local game client and fires when pre-game starts — hover, then lock, on whatever delays you set.

  4. 4

    Close the window

    It minimizes to the notification tray and keeps going. The loop survives the window, so the next queue is already covered.

Local API

Drive it from your own scripts.

On startup, Astral binds Kestrel to a random loopback port. It's 127.0.0.1 only, so nothing on your network can reach it. From there you can drive or watch the lock loop yourself.

GET/api/agents

Agent list from the local RadiantConnect enum

GET/api/agent-assets

The same list enriched with portraits, roles and colours

GET/api/state

Current lock state

GET/api/state/stream

The same state pushed on every change (SSE), with : ping keepalives in between

POST/api/lock

Start monitoring, or re-aim a running loop at another agent

POST/api/stop

Stop monitoring

GET/api/options

Settings plus the list of maps they can refer to

PATCH/api/options

Partial settings update, validated and persisted

POST /api/lock
Content-Type: application/json

{
  "agent": "Jett"
}
GET /api/state

{
  "isRunning": true,
  "isLocked": false,
  "selectedAgent": "Jett",
  "status": "Waiting for pre-game.",
  "error": null,
  "updatedAt": "2026-07-29T15:44:03.754Z"
}
PATCH /api/options
Content-Type: application/json

{
  "hoverDelayMs": 100,
  "lockDelayMs": 250,
  "postLockDelayMs": 5000,
  "mapAgentOverrides": {
    "Ascent": "Sova",
    "Haven": "Jett"
  }
}

Install

Grab the exe, or build it yourself.

The release is a single self-contained Astral.exe — no installer, no runtime to add, nothing written next to it. Prefer to compile? Three commands.

Download Astral.exe

You'll need

Windows 10 or 11

.NET 10.0 SDK, if you're building from source

Edge WebView2 Runtime, which is already on most modern Windows installs

Valorant running on the same machine

Configuration

Changes made in the UI or through the API are saved to %APPDATA%\Astral\settings.json. Defaults come from appsettings.json.

HoverDelayMs

Wait before hovering the agent in pre-game. 0–10000 ms, default 0.

LockDelayMs

Extra wait between hovering and clicking Lock. 0–10000 ms, default 0.

PostLockDelayMs

Idle time after locking, before the state resets. 0–10000 ms, default 5000.

MapAgentOverrides

Maps exact map names to canonical agent names. Empty by default.

  1. Clone it

    git clone https://github.com/CRZX1337/Astral-ValoTool.git
cd Astral-ValoTool

  2. Run it

    dotnet run -c Release

  3. Or publish a standalone exe

    Squeezes the runtime, the frontend and the WebView2 loader into a single self-contained Astral.exe (~62 MB) under bin\Publish\SingleFile\. That one file is everything you need to ship. 

    dotnet publish -p:PublishProfile=SingleFile

Details

Questions, and who built what.

What is it actually doing?

Astral talks to the Valorant client's own local API through RadiantConnect. It subscribes to pre-game events, and when one fires it calls select and then lock on your chosen agent. No screen reading, no input simulation.

Use at your own discretion.

Where does it store things?

Settings live in %APPDATA%\Astral\settings.json, with appsettings.json as the fallback. The embedded browser keeps its profile in %LOCALAPPDATA%\Astral\WebView2.

Nothing gets written next to the executable.

Can I script it instead of using the UI?

Yes. Everything the desktop UI does goes through the same local REST API, and /api/state/stream pushes state changes as Server-Sent Events so you never have to poll. See the API section.

Is anything exposed to my network?

No. Kestrel binds to a random port on 127.0.0.1 only, so nothing on your network can reach it.

Do I have to keep the window open?

No. Closing it sends Astral to the notification tray and the lock loop keeps running. Right-click the tray icon for Open, Stop locking or Exit.
